# Личный мост: внедрение

База: upstream 1.3.12, `2d6b0e24`. Рабочая ветка: `feature/reliable-private-bridge`.

Запрос: постоянная очередь; постоянные и полные привязки; исправление истории/поздних ответов/составных сообщений; форматирование; видеокружки; прочтение; закрепление; темы в личке бота.

## Работы

- [x] SQLite: журнал входящих Telegram updates, исходящих действий, связей сообщений/частей/опросов; восстановление после остановки.
- [x] Очередь с повторами, сохранёнными cid и проверкой неопределённой отправки; порядок действий в чате.
- [x] Курсор истории с включением временной границы и постоянной дедупликацией.
- [x] Защита от запоздавшего ответа после таймаута.
- [x] Полное редактирование составных сообщений в обе стороны; входящие правки также сохраняются в очереди с журналом новых Telegram-частей.
- [x] Форматирование Telegram entities ↔ MAX elements, включая разбиение UTF-16.
- [x] Отправка видеокружков с upload type 1 и videoType 1.
- [x] Команды прочтения и закрепления с проверкой владельца.
- [x] Темы в личке: настройка владельца, маршрутизация авторизации/команд/тем, отдельное состояние от прежней группы.
- [x] Регрессионные и интеграционные тесты, сборка, инструкции настройки/миграции/резервного копирования.

Старая аудиторская папка сохраняется как исходное свидетельство. Реальные токены и переписки не используются в тестах. Отдельно отмечать проверки на заглушках и реальную приёмку протокола.


## Что ещё требует владельца

- [x] Собственный Telegram-бот настроен: включены личные темы, токен проверен, ID владельца сохранён в локальном `.env`.
- [x] Мост запущен локально; Telegram polling подтверждён действующим процессом.
- [x] Пройти `/login` в личке бота; MAX-сессия подтверждена и восстановлена после перезапуска.
- [x] Провести реальную приёмку текста, правки, форматирования, кружков и прочтения в разрешённом владельцем MAX «Избранном». Закрепление там отклонено сервером; успешное выполнение в другом чате не проверялось.

Реализованные команды: `/queue`, `/retry`, `/canceljob`, `/retryincoming`, `/read`, `/pin`, `/unpin`. Прочтение явное: Bot API не сообщает боту о просмотре темы. Закрепление — управление MAX через команды. Неопределённый исход сетевой отправки сохраняется отдельно и не повторяется вслепую.

Настройка, миграция, резервная копия, ограничения: [PRIVATE_BRIDGE.md](PRIVATE_BRIDGE.md).


## Проверка реального подключения

Собственный Telegram-бот успешно отвечает на `getMe`, личные темы включены. Единственный владелец определён по его `/start`; токен/ключ находятся только в игнорируемом локальном `.env` с правами 600. Мост запущен локально, polling работает, Telegram принял приветствие.

Владелец настроил 2FA и успешно вошёл в MAX. После штатного перезапуска сохранённая сессия восстановилась без нового кода, токен обновлён, прежние привязки сохранены. Создана тема «Избранное» (MAX chat ID 0); владелец разрешил тестовую отправку только туда. Импорт реальной истории MAX → Telegram работает.

Живая проверка выявила зависание multipart-загрузок Telegraf на Node.js 26: локальный HTTP-приёмник не получает завершённое тело. На Node.js 24.19.0 тот же запрос завершился, и Telegram принял тестовый файл. Мост переведён на 24.19.0, неподдерживаемая версия останавливается до подключения. Пять ранее начатых входящих вложений сохранены как неподтверждённые и требуют сверки; автоматический повтор не разрешён.

Реально подтверждены исходящие текст и правка через постоянную очередь, форматирование с чтением обратно из MAX, отметка прочтения, native-кружок с чтением обратно и настоящий пользовательский кружок через очередь. Исправлены прямой протокол загрузки кружка и сохранение бинарного thumbhash в SQLite. MAX отклонил закрепление в «Избранном» («Не найдено»); успешная приёмка закрепления в другом чате не проводилась.

Владелец предпочёл отдельную группу вместо личных тем. Доставка переключена в закрытую группу «Max» с двумя участниками; проверены темы, права бота, перенос истории, нативные кружки и групповая очередь текста/правки/прочтения. Старые данные лички сохранены отдельно. Названия тем используют метку CUSTOM; существующие темы переименовываются, список тем создаётся до глубокой истории.

Проверено 508 автотестов в 44 файлах на Node.js 24.19.0, typecheck и сборка успешны. Текущая конфигурация и запуск описаны в PRIVATE_BRIDGE.md.

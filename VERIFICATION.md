Реально подтверждены: собственный Telegram-бот, личные темы, проверенный владелец, polling, вход MAX после настройки 2FA, импорт истории в темы, сохранение привязок и восстановление MAX-сессии после штатного перезапуска без кода. Telegram принял тестовый документ на Node.js 24.19.0. Создана тема «Избранное» MAX (ID 0); тестовая отправка разрешена владельцем только туда.

На Node.js 26.0.0 обнаружено зависание multipart-передачи Telegraf, не выявлявшееся тестами с подменённым API. Production поддерживает Node 22.19+ в ветке 22 и Node 24 LTS; установленный мост запущен на 24.19.0. Пять старых входящих отправок сохранены как неопределённые до ручной сверки, их курсоры не перескочили через вложения.

Реальная приёмка в MAX «Избранном»: отправка и чтение текста с STRONG; правка с сохранением форматирования; CHAT_MARK принят; synthetic native VIDEO/videoType=1 загружен и прочитан обратно; настоящий пользовательский кружок успешно прошёл очередь после исправления сериализации бинарного thumbhash. Текст и правка через очередь также подтверждены. После перехода в группу нативные кружки видны в Telegram; дополнительно выполнены текст с жирным выделением, его правка и `/read` через групповую очередь.

Закрепление в MAX «Избранном» отклонено сервером с «Не найдено». Payload совпадает с официальным веб-клиентом; успешная приёмка в другом MAX-чате не проводилась, поскольку владелец разрешил тесты только в «Избранном». Docker-образ дополнительно собран и проверен на Unit S (см. ниже). Upstream-установщик не запускался; автозапуск на Mac не настраивался.

По новому решению владельца активна закрытая группа «Max» с темами, а прежнее состояние лички сохранено отдельно. Темы получают метки CUSTOM вместо публичных ников; переименование существующей темы подтверждено в журнале. Сначала создаются все темы, затем переносится история. Инструкции: [PRIVATE_BRIDGE.md](PRIVATE_BRIDGE.md).

Исторические диагностические пробы и скачанные сторонние исходники сохранены локально в `research/` и не публикуются. Текущий набор проверок — `tests/**/*.test.ts`.

## Перенос на Unit S

По прямому выбору владельца мост перенесён в `/srv/telemax` на Unit S. На Node.js 24.22.1 в Linux-контейнере проходят TypeScript и 515/515 тестов. Официальный Node 24-slim закреплён по digest в обеих стадиях Dockerfile.

Исправлена проверенная предсетевая ошибка EADDRNOTAVAIL: она больше не считается неизвестным исходом отправки; старые диагностированные записи также могут безопасно повторяться. Для ECONNRESET, ETIMEDOUT и записей без подтверждённой причины блокировка слепого повтора сохранена. Добавлено семь проверок.

После остановки Mac создан согласованный снимок обеих SQLite-баз, тем, сессии и настроек. На сервере проверены целостность SQLite, исходные количества всех записей и расшифровка сессии без вывода секретов. MAX восстановил вход, Telegram polling активен. Контрольная отправка через Telegram UI в Избранное принята MAX с серверного экземпляра (задание 4, done). Docker работает с restart=unless-stopped и включён в загрузку системы; входящих портов нет, приложение UID 1000. Mac остановлен, локальный повторный запуск защищён маркером.

Операционные инструкции с адресами сервера хранятся отдельно от публичного репозитория. Общий порядок отката — в [PRIVATE_BRIDGE.md](PRIVATE_BRIDGE.md). Полная перезагрузка Unit S не проводилась; остальные службы не менялись.

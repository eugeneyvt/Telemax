# Личный мост MAX ↔ Telegram

Эта версия добавляет постоянную доставку и темы в личке Telegram-бота либо в отдельной закрытой группе. Для большого списка чатов удобнее группа с темами. Код основан на upstream 1.3.12; это самостоятельная доработка, а не официальный релиз upstream.

## Настройка

1. Создать собственного бота через BotFather, включить у него Forum/Topics mode для личных чатов. В ответе `getMe` поле `has_topics_enabled` должно быть `true`.
2. Отправить боту `/start` со своего аккаунта. В `.env` указать именно числовой **ID своего Telegram-аккаунта**, не номер телефона и не username.
3. Скопировать `.env.example` в новый `.env`, заполнить:

   ```dotenv
   TELEGRAM_BOT_TOKEN=токен_собственного_бота
   TELEGRAM_CHAT_MODE=private
   TELEGRAM_OWNER_ID=числовой_ID_владельца
   MAX_SESSION_KEY=64_шестнадцатеричных_символа
   FILES=off
   ```

   Сгенерировать ключ: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`.
   Для `.env` нужны права `600`. Токен и ключ не добавлять в Git.
4. Для первого запуска этой ветки использовать локальную сборку. Node.js **24 LTS** (также поддерживается ветка 22 начиная с 22.19) с `node:sqlite`:

   ```bash
   npm ci
   npm run build
   npm start
   ```

   Альтернатива на сервере с Docker: `docker compose up -d --build`. Docker хранит данные в `./data`, прямой запуск — в `./.data`. Docker-образ проверен на Linux с Node.js 24.22.1 в режиме `STICKERS=slim`. `setup.sh` также предлагает выбор лички/группы для новой установки, но сам установщик в этой доработке не проходил полную приёмку.
5. В личке бота отправить `/login`, ввести номер MAX, код и при необходимости пароль. Если MAX отвечает «Требуется установить 2FA», сначала на устройстве с действующим входом открыть MAX → Настройки → Безопасность → Пароль для входа и установить пароль, затем начать новый `/login`. Это условие самого MAX для нового устройства; повтор прежнего SMS-кода не помогает. Выбрать глубину истории. Чаты MAX появятся отдельными темами; писать нужно в соответствующую тему.

Без токена бота, ID владельца и входа в MAX реальная пересылка не запускается. Получить SMS и включить темы BotFather должен владелец аккаунтов. Авторизация не записывается в очередь сообщений.

В этой ветке не использовать обновление на upstream через `/version`, `update.sh` или удалённый установщик из прежней инструкции: они устанавливают подписанные upstream-релизы без этих доработок. Обновлять свою проверенную ветку вручную с резервной копией данных.

## Управление

Дополнительные команды собраны в `/tools`. Меню Telegram также содержит тихую и отложенную отправку, пересылку, профиль, устройства и папки.

| Действие | Как выполнить |
| --- | --- |
| Переписка | Писать в теме нужного MAX-чата |
| Форматирование | Стандартное оформление Telegram; жирный, курсив, подчёркивание, зачёркивание, код, блок кода, цитата, ссылка |
| Видеокружок | Отправить настоящий Telegram video note; в MAX создаётся native VIDEO с `videoType: 1`, а не обычный ролик |
| Прочтение | Ответить `/read` на сообщение или отправить `/read` в теме для последнего сохранённого входящего |
| Закрепить в MAX | Ответить `/pin` на нужное сообщение |
| Снять закрепление в MAX | `/unpin` в теме |
| Проверить доставку | `/queue` показывает до 30 незавершённых исходящих заданий и неопределённые входящие отправки |
| Повтор после устранения ошибки | `/retry НОМЕР`; неизвестный исход сначала сверяется по cid |
| Остановить исходящее задание | `/canceljob НОМЕР ПОДТВЕРЖДАЮ`; журнал сохраняется, уже принятое MAX сообщение не удаляется |
| Вручную разрешить входящий повтор | После сверки в Telegram: `/retryincoming MAX_CHAT:MAX_MESSAGE:TOPIC ПОДТВЕРЖДАЮ`. Если Telegram уже принял часть без подтверждения, возможна её повторная копия |
| Тихая отправка | `/silent текст`, сохраняет оформление и ответ на оригинал |
| Отправить позже | `/schedule +30m текст`, `+2h`, `+1d` или ISO-время с явным часовым поясом |
| План и отмена | `/scheduled` показывает будущие сообщения, созданные **через мост** в этой теме; `/unschedule номер` отменяет их в MAX |
| Нативная пересылка MAX | Ответ `/forward НОМЕР_ТЕМЫ`; номер темы есть в её Telegram-ссылке |
| Устройства MAX | `/devices`; завершение остальных входов: `/devices close ПОДТВЕРЖДАЮ`. Новый MAX-токен сохраняется зашифрованным |
| Профиль | `/profile`; изменение: `/profile Имя \| Фамилия \| Описание` |
| Фото профиля | `/avatar` ответом на выбранное фото; имя сохраняется |
| Папки MAX | `/folders`, `/folderadd Название`, `/folderrename ID Название`, `/folderinclude ID`, `/folderexclude ID`, `/folderdelete ID УДАЛИТЬ` |
| Реакции MAX | Карточка всех счётчиков, включая emoji вне списка Telegram; `/reactions` ответом обновляет значения |

Альбомы из Telegram собираются в постоянной очереди после двух секунд без новых частей; все части связываются с одним MAX-оригиналом. Совместимые фото/видео и группы файлов MAX приходят Telegram-альбомами. Кружки остаются отдельными круглыми видео. Замена фото/видео/файла синхронизируется в обе стороны; правка одной части сохраняет соседние вложения и подписи. Бот не может менять сообщение, написанное самим владельцем в Telegram: для последующих правок из MAX он создаёт собственную обновлённую копию, сохраняя связь с оригиналом.

Опросы MAX показываются карточками с кнопками и настоящими MAX-счётчиками. Можно голосовать и в анонимных опросах: выбор варианта сначала локальный, «Отправить голос» подтверждает действие от MAX-аккаунта владельца. Переголосование/снятие голоса доступны, только если автор разрешил их в MAX; закрытые опросы остаются доступными для просмотра. Голосовать нужно кнопками карточки MAX, а не исходным пользовательским Telegram-опросом: Bot API не передаёт боту голоса за чужие опросы.

Прочтение собеседником отображается по событиям MAX отдельной обновляемой карточкой. Это время границы прочтения, а не доказательство просмотра каждого вложения. Реальные read marks другого человека нельзя проверить в чате с самим собой; разбор события и восстановление проверяются автотестами.

MAX-стикеры, которые уже проходили через мост, можно отправить обратно с исходной MAX-идентичностью. Прочие статичные/анимированные Telegram-стикеры преобразуются в поддерживаемый медиаформат; для анимаций нужен образ `STICKERS=full` с Chromium и ffmpeg. Полный перенос произвольного Telegram sticker set в native MAX sticker pack не заявляется.

Пределы обычного Bot API остаются: скачивание Telegram-файла до 20 МБ; отправка ботом обычного файла до 50 МБ, фото до 10 МБ. Расширение через локальный Telegram Bot API server исключено владельцем. Нативные звонки, Mini Apps и цифровые сервисы MAX в Bot API не переносятся. Обычный Telegram-бот также не получает событие набора текста или просмотра темы владельцем. Telegram хранит неполученные updates до 24 часов: очередь защищает уже принятые updates, но не обещает восстановление после неограниченного простоя.

Независимый монитор, watchdog и согласованные резервные копии описаны в [deploy/README.md](deploy/README.md). Источники и проверка полного объёма расширения — [EXPANSION.md](EXPANSION.md).

Telegram Bot API не сообщает боту, что владелец прочитал сообщение: автоматическая отметка MAX при просмотре темы невозможна. Поэтому прочтение реализовано явной командой. Закрепление управляется командами MAX; автоматическое зеркалирование всех изменений закрепов между приложениями не заявляется. Право закреплять в чужих MAX-группах определяется самим MAX.

Spoiler и custom emoji Telegram не имеют подтверждённого эквивалента MAX: видимый текст сохраняется без такого оформления. MAX-упоминания отображаются выделенным текстом; ID пользователей разных сервисов не подменяются друг другом. Кружки сохраняют ограничения размера Telegram Bot API: для загрузок свыше 20 МБ используется существующий отдельный файловый маршрут, требующий настройки файлового сервиса.

## Доставка и хранение

- SQLite `.data/telegram-ID/bridge.sqlite` — очередь Telegram updates, результаты исходящих действий, cid и привязки всех частей MAX/Telegram, включая служебные сообщения и опросы. В Docker этот путь находится внутри смонтированного `data/`.
- WAL и `synchronous=FULL`; каждый update сохраняется **до** передачи poll batch обработчику Telegram. В одном чате сохраняется порядок, ошибочное задание блокирует следующие задания этого чата. Другие чаты продолжают работать.
- Подтверждённые исходящие части не отправляются повторно после перезапуска. Если ответ MAX потерялся, журнал ищет положительное совпадение cid в push/истории. Отсутствие совпадения не считается доказательством недоставки: задание остаётся `uncertain`.
- Каждая подтверждённая входящая часть получает постоянную промежуточную привязку. После прерывания известные неполные копии бота удаляются перед повторной доставкой оригинала. При потере ответа Telegram сохраняется намерение отправки, автоматический повтор останавливается; ситуация видна в `/queue`. Bot API не позволяет узнать ID принятого сообщения по произвольному клиентскому ключу.
- RAM-кэши ограничены, привязки на диске не вытесняются после 500 сообщений и не исчезают при обычном перезапуске. Один файл базы может использовать только один процесс моста: отдельный SQLite-файл `.lock` удерживает файловую блокировку ОС до завершения процесса, включая автоматическое освобождение после аварии. Повторное использование PID контейнером не мешает восстановлению. Смена MAX-аккаунта без отдельного состояния блокируется.
- История запрашивается с перекрытием временной границы; повторы фильтруются по постоянным ID. Если границу или предел страниц нельзя уверенно пройти, синхронизация не объявляет историю догнанной.
- После таймаута MAX закрывается прежнее соединение: его поздний ответ не может стать ответом на следующее действие.
- Правки текста увеличивают/уменьшают количество частей в обе стороны, сохраняют их ID и удаляют лишние хвосты. Входящие правки MAX также сохраняются в общей очереди до обработки; добавленные части Telegram имеют журнал подтверждений. Повтор одного push дедуплицируется, последующая отмена правки на прежний текст остаётся отдельной операцией. Медиа и служебные сообщения не принимаются за текстовые части.

Абсолютная гарантия «ровно один раз» при потере сетевого подтверждения недостижима средствами этих API. Реализовано сохранение подтверждённых результатов, безопасный повтор известных отказов и отдельное видимое состояние для неизвестного результата. Свободное место и работоспособность диска остаются необходимыми условиями.

Журнал содержит текст и метаданные сообщений, **не шифруется** отдельно от диска и сохраняет завершённые/отменённые задания. Сессия MAX использует существующее шифрование ключом `MAX_SESSION_KEY`. `/kill` отключает сессию и очищает активные привязки, но не является физическим стиранием архивных записей SQLite.

## Миграция, резервная копия, откат

Личный режим получает отдельный каталог состояния `telegram-ID`; старые темы группы автоматически не переименовываются в темы лички. Групповой режим выбирается явно: `TELEGRAM_CHAT_MODE=group`, отрицательный `TARGET_TELEGRAM_GROUP`; положительный `TELEGRAM_OWNER_ID` обязателен и ограничивает все действия одним владельцем. Старое `chat-map.json` не переносится автоматически: прежние привязки, существовавшие только в памяти upstream, восстановить после остановки нельзя. Для перехода безопаснее новый бот и отдельный экземпляр с новой заливкой истории.

Перед переносом/откатом остановить мост и скопировать **весь** фактически используемый `data/` либо `.data/` вместе с `.env`. Нельзя копировать один открытый `bridge.sqlite`, оставив его WAL. Сохранить исходную ветку и конфигурацию. Откат к upstream выполнять с прежней группой и её прежним состоянием, сохранив новый каталог SQLite отдельно; старый код не умеет продолжать новую очередь. Формат базы более новой версии намеренно не открывается старым кодом.

## Приёмка

Автотесты используют реальные обработчики Telegraf, временную SQLite, процесс с аварийным выходом и имитацию сетевых API. Они не используют реальные токены/переписки. Перед использованием на основном аккаунте проверить с тестовым собеседником: текст и форматирование; 4096 символов и последующую правку; ответ на старое сообщение после перезапуска; кружок в обе стороны; `/read`, `/pin`, `/unpin`; отключение связи и восстановление очереди. Проведённые проверки на действующем аккаунте и оставшиеся ограничения перечислены в [VERIFICATION.md](VERIFICATION.md).


## Локальный runtime и Избранное

Используйте Node.js 24 LTS (допускается также ветка 22 начиная с 22.19). На Node.js 26 Telegraf 4 зависает при multipart-загрузке файлов; проверка при запуске запрещает такой runtime. Успех JSON-запросов или тестов с подменённым API не доказывает работоспособность загрузки вложений.

Команда `/saved` проверяет у MAX наличие чата ID 0 и открывает тему «Избранное». Если MAX его не возвращает, другой чат автоматически не выбирается.


## Текущая локальная установка — 24.10.2026

По выбору владельца рабочая доставка переключена из лички в закрытую Telegram-группу с темами. Участники при настройке: владелец и бот. База и карта тем находятся в `.data/telegram-ID/` для выбранного получателя; прежние данные лички сохранены отдельно. ID сообщений между этими получателями не переносятся.

Рабочая конфигурация: `.data/runtime-secret.env`, права 600, Git игнорирует файл. Он выбран после повторной внешней перезаписи исходного `.env`; причина этой перезаписи не установлена. В нём остаются токен, ключ шифрования и прежний ID владельца. Резервная конфигурация до перехода на группу: `.data/runtime-secret.before-group.env`. Файлы с секретами не публиковать.

Локальный запуск: `npm run start:local`. Он выбирает проверенный Node.js, читает сохранённую конфигурацию, записывает журнал в `.data/local-bridge.log`; PID и время запуска находятся в `.data/local-bridge-process.json`. После изменения исходников сначала выполнить `npm run build`. Автозапуск после перезагрузки компьютера пока не устанавливался.

Темы личных MAX-диалогов называются по пользовательской метке CUSTOM. При её отсутствии используется обычное имя; заголовки MAX-групп и «Избранное» сохраняются. Уже созданные темы переименовываются при синхронизации; карточки профилей продолжают показывать имя человека. Сначала создаётся список тем, затем переносится длинная история.

В реальной проверке MAX принял текст, форматирование, правку, прочтение и два видеокружка в «Избранном». Текст, правка и пользовательский кружок прошли постоянную очередь; кружки вернулись в группу в круглом виде. `/read` в группе также выполнен через очередь. На запрос закрепления в MAX «Избранном» сервер ответил «Не найдено»; успешное закрепление в другом MAX-чате в рамках разрешённой проверки не подтверждалось. В личке Telegram политика владельца запрещает боту присылать кружки — там применяется fallback в обычное видео; в группе нативные кружки принимаются.


## Рабочий сервер

С 24.10.2026 активен Unit S: каталог `/srv/telemax`, сервис Docker Compose `telemax`, контейнер `telemax-telemax-1`. Mac больше не запускает мост; его выключение или сон не останавливают серверную пересылку. Текущая серверная конфигурация находится в `/srv/telemax/.env`; локальная `.data/runtime-secret.env` является прежней копией, а не рабочим источником серверного состояния.

Исходная локальная инструкция выше сохранена для разработки и восстановления. Обычный `npm run start:local` после переноса блокируется маркером `.data/server-active.json`. Откат требует сначала остановить сервер и скопировать его актуальное состояние обратно — MAX-сессия и очередь уже обновляются на сервере. Порядок копирования описан выше в разделе «Миграция, резервная копия, откат»; адреса сервера и частные операционные инструкции хранятся отдельно от публичного репозитория.
